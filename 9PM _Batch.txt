Variables :
-------------

In JavaScript we can declare variables using three keywords: var , let , const.

let name1="Rahul"

-> Here , name1 , age , college are variables

-> The const keyword is used when we do not want to re-assign a variable.

If i write let age=20; it means I am creating a variable called age
and storing the value 20 in it.

*** In Modern JavaScript, we generally prefer let and const.

Encapsulation :
---------------
Suppose you have a bank account . Should everyone be allowed to change your balance directly ? No . 	A bank needs rules for depositing and withdrawing money.

Encapsulation means grouping data and realted methods together and controlling how the data can be accessed or changed.

In JavaScript , we can use private fields , written with #, to prevent outside code from directly accessing those fields.

class BankAccount
{
    #balance; // 5000
    constructor(initialBalance) // initialBalance=5000 is update once object creating
    {
       this.#balance=initialBalance; 

    }
    deposit(amount)
    {
        if(amount>0) // 2000 >0
        {
            this.#balance+=amount; // this.#balance=this.#balance+amount;

            // this.#balance= 5000+2000;
            //this.#balance=7000;
        }
    }
    getBalance()
    {
        return this.#balance;
    }

}
const account = new BankAccount(5000);
account.deposit(2000)
// account.#balance=900000000000000000000000000000000000000000000000000000000n;

console.log(account.getBalance())























Inheritance :
-------------
Imagine that Animal is a General class (Parent). A dog and a cat are both animals. They have common characterstics, such as eating , but they can also perform different actions.

Instead of writing the same common code repeatedly, we can create a parent class and let child classes inherit from it.


Parent Class or Super Class or Base Class: The class whose behaviour is inherited

Child Class : The class that extends another class.

extends : Establish class inheritance

super() : Calls the parent class constructor when initializing a derived class.


class Animal 
{
    constructor(name)
    {
        this.name=name;
    }
    eat()
    {
        console.log(this.name+" is eating")
    }

}

class Dog extends Animal{
    bark()
    {
        console.log(this.name+ " is barking")
    }
}
class Cat extends Animal{
    meow()
    {
        console.log(this.name+" Says meow")
    }
}

const dog=new Dog("Tommy");
const cat= new Cat("Kitty");
dog.eat()
dog.bark()
cat.eat()
cat.meow()

Assertions in Playwright :
---------------------------

What is an Assertion ?

Suppose we are testing a login application.

Test Scenario:

1. Open the application
2. Enter Username
3. Enter Password
4. Click Login
5. Verify whether the dashboard is displayed.
import {test,expect} from '@playwright/test'

test('Verify Login Functionality',async({page})=>{

    await page.goto("https://techwithsuresh.lovable.app/shop/login");
    await page.locator('#email').fill("demo@shopease.test");
    await page.locator('#password').fill("Demo@123");
    await page.getByTestId("login-submit").click();

    // Assertions

    await expect(page.getByTestId("shop-demo-banner")).toBeVisible();

})

Expected Result : Dashboard should be visible after  successful login.

If the dashboard is not visible , the assertion fails and Playwright marks the test
as failed.

Types of Assertions:

1. Auto retrying Assertions
Used to verify web elements and their properties . Playwright automatically retries
untill the condition passes or times out.

toBeVisible();

2. Non retrying Assertions

Used to verify immediate values , arrays , objects , and other data.

example: toEqual();


3. Soft Assertions


Test execution Continues even when an assertion failes and failures are reported
 at the end of the test.

 expect.soft();

Non - Retrying Assertions (or) Generic Values assertions:
==========================================================

Validate the current value immediately. They do not automatically retrying
when the assertion fails


Imagine we have a variable conatining the employee Name

let employeeName= "Suresh";
Now we want to verify whether the employee name is Suresh


We write :

expect(employeeName) . toBe("Suresh")

Playwright checks the current value immediately.

If the condition is true ,  the assertion is passes
If the condition is false , the assertion fails immediately


It does not wait  for the value to change.


Syntax:

expect(actualValue).matcher(expectedValue);

let age : number = 27;

expect(age).toBe(27)

Important: 

Non retrying assertions are appropriate for JavaScript values calculation , API statuscodes
, and already retrived data. They are not suitable when you need to wait fr a browser
element or page state to change.

1. toBe() - Checks whether the actual value is the exactly the Expected
value.

let age : number = 27;

expect(age).toBe(27)



2. toEqual() : Checks whether two values have equivalent contents using 
               deep equality

test('ToEQUAL Assertion',async()=>{

let actualEmployee= {
     id : 101,
     name : "Suresh",
     department : "Testing"


};

let expectedEmployee={


    id : 101,
    name : "Suresh",
    department : "Testing"
};

expect(actualEmployee).toEqual(expectedEmployee)

})

toBe() and toEqual() are different.

toBe() checks whether two  values are the same according to Object.is()

toEqual() checks whether objects or arrays have equivalent contents

toStrictEqual():
----------------

Checks deep equality more strict, including distinctions such as Undefined
properties and sparse arrays.

   expect(actual).toStrictEqual(expected)
